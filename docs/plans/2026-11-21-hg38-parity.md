## Open findings that this plan settles

### The gene order of UNION and LONGEST

The finding of `tmp/claude/SESSION.md` states that R `split` sorts the gene IDs in the collation order of the locale. The planner probes show that this is not correct:

- `GenomicRanges::split` of a `GRanges` calls `IRanges:::default_splitAsList`. For a character `f`, it calls `IRanges:::.as_factor`, which sorts the levels with `order(levs, method = "radix")` (IRanges 2.44.0). A radix order of R is the C-locale order, thus the code-point order of the UTF-8 text.
- `.get_longest_utr` groups with `dplyr::group_by`. dplyr 1.2.1 sorts the groups in the C locale.
- Probe `order_probe.R` reads each gene ID of the hg38 EnsDb, with the prefixes `ENSG` and `LRG_`. In the C locale and in `en_US.UTF-8`, the order of `split` and of `group_by` is `sort(ids, method = "radix")`.
- Probe `order_fixture.R`, on a copy of the fixture EnsDb with the gene IDs `ensSYNG00000000001`, `gene_b`, `gene-a`, `Gene10`, and `gene9`: `load_annotations` with the patched `reduce.features` gives `ENSSYNG00000000002 Gene10 ensSYNG00000000001 gene-a gene9 gene_b` in the two locales. `longest.utr` gives the genes in the same order. In `en_US.UTF-8`, base R `sort` gives `ensSYNG00000000001 ENSSYNG00000000002 gene_b gene-a Gene10 gene9`.

The port sorts the gene IDs with `np.unique` (`_longest` and `_union` of `src/seedmatch/annotation/features.py`), thus by code point. The port and R agree for each ID shape and each locale, thus there is no divergence. Task 2 adds a test that keeps this order. The controller removes the finding from `tmp/claude/SESSION.md`.

- [ ] **Step 1: Move the loop of `annotation_rnor7.R` into `annotation_common.R`.** Append this function to `annotation_common.R`. It replaces `digests_table` and the loop of `annotation_rnor7.R`:

```r
# Write tests/golden/annotation/<build>/<config>.tsv.gz for each config. The EnsDb and the 2bit file
# are in file.path(SEEDMATCH_TEST_REFS, build). The feature sequences of a real reference are too
# large for a golden file. tests/annotation/test_refs.py computes the same digest from the
# uppercase text of each sequence.
write_reference_goldens <- function(build, ensdb, twobit, configs, script) {
  if (!requireNamespace("openssl", quietly = TRUE)) {
    stop("the R package openssl is not installed; ", script, " needs it for the digests")
  }
  refs <- Sys.getenv("SEEDMATCH_TEST_REFS")
  if (!nzchar(refs)) {
    stop("SEEDMATCH_TEST_REFS is not set; set it to the directory that holds ", build, "/")
  }
  directory <- file.path(refs, build)
  txdb <- ensembldb::EnsDb(file.path(directory, ensdb))
  dna <- rtracklayer::TwoBitFile(file.path(directory, twobit))
  utils::assignInNamespace("load_species_anno_db", local_anno_db(txdb, dna), ns = "SeedMatchR")
  reference <- paste0("reference: ", build, "/", ensdb, ", ", build, "/", twobit)
  for (name in configs) {
    started <- Sys.time()
    run <- run_config(name, ANNOTATION_CONFIGS[[name]])
    digests <- sequences_table(run$result)
    digests$digest <- substr(as.character(openssl::sha256(digests$sequence)), 1, 16)
    digests$sequence <- NULL
    path <- paste0("annotation/", build, "/", name, ".tsv.gz")
    write_golden(digests, path, script, c(run$notes, reference))
    seconds <- as.numeric(difftime(Sys.time(), started, units = "secs"))
    cat(name, ": ", nrow(digests), " rows, ", round(seconds), " s\n", sep = "")
  }
}
```

**Files:**

**Interfaces:**

- Produces, in `test_refs.py`: `Build` (a `NamedTuple` with `gtf: str`, `gtf_size: int`, `gtf_sha256: str`, `configs: tuple[str, ...]`), `BUILDS: dict[str, Build]`, `pinned_files(build_id) -> dict[str, tuple[int, str]]`, `open_ensdb(refs_dir, build_id) -> Reference`, and the fixtures `refs_dir`, `build`, `ensdb_ref`, and `gtf_ref`.

The fixtures obey these rules:

- The tests that use `build` take it from a module fixture with `params`. pytest groups these tests by build. It closes `ensdb_ref` and `gtf_ref` of one build before it opens the next build.
- A test parametrized with pairs of a build and a config does not use `build`. A planner run gave such a test an indirect `build`. Then pytest 9.2.0 set up `build` and `ensdb_ref` again for each pair, also for two pairs of one build (`--setup-show`).

```python
import hashlib
import os
from pathlib import Path
from typing import NamedTuple

import numpy as np
import pandas as pd
import pytest
from annotation_cases import ALL, CASES
from helpers import golden

from seedmatch.annotation.filters import FeatureType, PerGene
from seedmatch.annotation.reference import Reference
from seedmatch.resources import Group, lookup

pytestmark = pytest.mark.refs


class Build(NamedTuple):
    gtf: str
    gtf_size: int
    gtf_sha256: str
    configs: tuple[str, ...]


RNOR7_CONFIGS = ("utr3", "utr5", "exons", "cds", "utr3_longest", "utr3_union")
# The registry has no GTF file, so this file pins the GTF of each build.
BUILDS = {
    "rnor7": Build(
        "Rattus_norvegicus.mRatBN7.2.109.gtf.gz",
        18029537,
        "ff7d5ecd69ed7df5e641ec90383e5de9e10e9d82316a0570c71fa80a98e8edca",
        RNOR7_CONFIGS,
    ),
    "hg38": Build(
        "Homo_sapiens.GRCh38.109.gtf.gz",
        54258835,
        "1ce4b88d9283f70220c318ebb3e654a9b5815316b9ba4c9b93564f29f10fab29",
        (*RNOR7_CONFIGS, "entrez", "tsl1"),
    ),
}


def pinned_files(build_id):
    twobit, ensdb = lookup(Group.REFERENCE, build_id).resources
    build = BUILDS[build_id]
    return {
        ensdb.name: (ensdb.size, ensdb.sha256),
        twobit.name: (twobit.size, twobit.sha256),
        build.gtf: (build.gtf_size, build.gtf_sha256),
    }


FILES = [(build_id, name) for build_id in BUILDS for name in pinned_files(build_id)]
CONFIGS = [(build_id, config) for build_id, build in BUILDS.items() for config in build.configs]


@pytest.fixture(scope="module")
def refs_dir():
    refs = os.environ.get("SEEDMATCH_TEST_REFS")
    if not refs:
        pytest.skip("SEEDMATCH_TEST_REFS is not set")
    return Path(refs)


# The GTF reference of hg38 holds about 1 GB. A module fixture with params groups its tests by
# build, so pytest closes the references of one build before it opens the next build.
@pytest.fixture(scope="module", params=list(BUILDS))
def build(request):
    return request.param


def present(directory, name):
    path = directory / name
    if not path.is_file():
        pytest.skip(f"{path} is absent")
    return path


def open_ensdb(refs_dir, build_id):
    directory = refs_dir / build_id
    twobit, ensdb = lookup(Group.REFERENCE, build_id).resources
    present(directory, ensdb.name)
    present(directory, twobit.name)
    return Reference.from_directory(directory)


@pytest.fixture(scope="module")
def ensdb_ref(refs_dir, build):
    with open_ensdb(refs_dir, build) as ref:
        yield ref


@pytest.fixture(scope="module")
def gtf_ref(refs_dir, build):
    directory = refs_dir / build
    twobit, _ = lookup(Group.REFERENCE, build).resources
    gtf = present(directory, BUILDS[build].gtf)
    with Reference.from_gtf(gtf, present(directory, twobit.name)) as ref:
        yield ref


def digest16(sequences):
    return [
        hashlib.sha256(sequences.sequence(i).encode("ascii")).hexdigest()[:16]
        for i in range(len(sequences))
    ]


def assert_same_sequences(got, expected):
    assert len(expected) > 0
    assert got.ids == expected.ids
    assert got.gene_ids == expected.gene_ids
    np.testing.assert_array_equal(got.offsets, expected.offsets)
    np.testing.assert_array_equal(got.codes, expected.codes)


@pytest.mark.parametrize(("build_id", "name"), FILES)
def test_files_are_the_pinned_files(refs_dir, build_id, name):
    path = present(refs_dir / build_id, name)
    size, sha256 = pinned_files(build_id)[name]
    assert path.stat().st_size == size
    with path.open("rb") as file:
        assert hashlib.file_digest(file, "sha256").hexdigest() == sha256


# The builds have different configs. pytest sets up an indirect fixture again for each pair of a
# build and a config, so this test opens the EnsDb itself.
@pytest.mark.parametrize(("build_id", "config"), CONFIGS)
def test_sequences_match_r(refs_dir, build_id, config):
    case = CASES[config]
    with open_ensdb(refs_dir, build_id) as ref:
        got = ref.sequences(
            case.feature, case.transcript_filter, per_gene=case.per_gene, min_width=case.min_width
        )
    expected = golden(f"annotation/{build_id}/{config}.tsv.gz")
    # For a union, R puts the gene ID in name_tx and NA in name_gene (D-002), so the gene IDs come
    # from name_tx.
    gene_ids = "name_tx" if case.per_gene is PerGene.UNION else "name_gene"
    assert list(got.ids) == expected["name_tx"].tolist()
    assert list(got.gene_ids) == expected[gene_ids].tolist()
    assert got.lengths().tolist() == expected["width"].astype(int).tolist()
    assert digest16(got) == expected["digest"].tolist()


@pytest.mark.parametrize("feature", list(FeatureType))
def test_gtf_gives_the_sequences_of_the_ensdb(ensdb_ref, gtf_ref, feature):
    assert_same_sequences(gtf_ref.sequences(feature, ALL), ensdb_ref.sequences(feature, ALL))


def test_gtf_union_gives_the_sequences_of_the_ensdb(ensdb_ref, gtf_ref):
    assert_same_sequences(
        gtf_ref.sequences(FeatureType.UTR3, ALL, per_gene=PerGene.UNION),
        ensdb_ref.sequences(FeatureType.UTR3, ALL, per_gene=PerGene.UNION),
    )


# The row order breaks a tie of the width and the start, and the GTF has another row order than the
# EnsDb. Thus a tie can select another transcript of the gene, and the test compares the widths.
def test_gtf_longest_gives_the_widths_of_the_ensdb(ensdb_ref, gtf_ref):
    expected = ensdb_ref.sequences(FeatureType.UTR3, ALL, per_gene=PerGene.LONGEST)
    got = gtf_ref.sequences(FeatureType.UTR3, ALL, per_gene=PerGene.LONGEST)
    assert len(expected) > 0
    assert got.gene_ids == expected.gene_ids
    np.testing.assert_array_equal(got.lengths(), expected.lengths())


# The row order breaks a tie of the contig and the start (D-030), and the GTF has another row order
# than the EnsDb. Thus the test compares the transcripts in the order of tx_id.
def test_gtf_gives_the_transcripts_of_the_ensdb(ensdb_ref, gtf_ref):
    expected = ensdb_ref.transcripts(ALL).sort_values("tx_id", ignore_index=True)
    got = gtf_ref.transcripts(ALL).sort_values("tx_id", ignore_index=True)
    assert len(expected) > 0
    pd.testing.assert_frame_equal(got, expected)
```

```python
# R sorts the genes of reduce.features with IRanges:::.as_factor, which calls order(method =
# "radix"), and the genes of longest.utr with dplyr::group_by in the C locale. Thus R sorts the
# gene IDs by code point in each locale, also where the collation of the locale gives another order.
CODE_POINT_GENE_IDS = {
    "ENSSYNG00000000001": "ensSYNG00000000001",
    "ENSSYNG00000000005": "gene_b",
    "ENSSYNG00000000006": "gene-a",
    "ENSSYNG00000000007": "Gene10",
    "ENSSYNG00000000008": "gene9",
}
CODE_POINT_ORDER = [
    "ENSSYNG00000000002",
    "Gene10",
    "ensSYNG00000000001",
    "gene-a",
    "gene9",
    "gene_b",
]


@pytest.mark.parametrize(
    ("per_gene", "ids"),
    [
        (PerGene.UNION, CODE_POINT_ORDER),
        (
            PerGene.LONGEST,
            [
                "ENSSYNT00000000003",
                "ENSSYNT00000000010",
                "ENSSYNT00000000002",
                "ENSSYNT00000000009",
                "ENSSYNT00000000012",
                "ENSSYNT00000000008",
            ],
        ),
    ],
)
def test_per_gene_orders_the_gene_ids_by_code_point(tmp_path, per_gene, ids):
    path = copy_ensdb(
        tmp_path,
        *(
            f"UPDATE {table} SET gene_id = '{new}' WHERE gene_id = '{old}'"  # noqa: S608
            for old, new in CODE_POINT_GENE_IDS.items()
            for table in ("gene", "tx", "entrezgene")
        ),
    )
    db = AnnotationDb.open(path)
    got = derive_features(db.exon_rows(ALL, coding_only=True), FeatureType.UTR3, per_gene)
    db.close()
    assert list(got.gene_ids) == CODE_POINT_ORDER
    assert list(got.ids) == ids
```

  Notes:
  - The expected values are the R result of the planner probe `order_fixture.R`, with R 4.5.3 in `LC_ALL=C` and in `LC_ALL=en_US.UTF-8`.
  - The R expressions are `names(load_annotations(..., reduce.features = TRUE)$features)` with the patch `reduce_features.R`, and `names(load_annotations(..., longest.utr = TRUE)$features)`. Each call has `canonical = FALSE` and `min.feature.width = 0`.
  - The port gives the same values (`order_fixture.py`).
  - A sort in the collation of `en_US.UTF-8` puts `ensSYNG00000000001` before `ENSSYNG00000000002`, thus it fails the test.
